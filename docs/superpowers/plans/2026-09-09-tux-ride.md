# Tux Ride 🐧👑 — Emperor Penguin Mount Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the "Tux Ride" feature in `tux_script.lua`, spawning a rideable 3D procedural Emperor Penguin mount with interactive mounting (`ProximityPrompt` / `ClickDetector`), responsive WASD physics, and synchronized dual animations (penguin waddle/slide + rider lean/reins).

**Architecture:** A client-side procedural 3D model parented to `Workspace` with collision-exempt parts, carrying a customized seat and interactive triggers. A dedicated RenderStepped physics & animation loop calculates surface raycasts, turning inertia, waddling steps, ice belly-slide drift with particle emitters, and procedural rider posture. Seamlessly integrated into the "Fun" category of Tux Script GUI with full cleanup and auto-respawn resilience.

**Tech Stack:** Luau / Lua 5.1+, Roblox Engine APIs (`Workspace`, `RunService`, `TweenService`, `UserInputService`, `ProximityPrompt`, `ClickDetector`, `Raycasting`).

## Global Constraints
- **Platform:** Roblox Client Executor / Universal Lua script.
- **Syntax Compatibility:** Valid Lua 5.1 / Luau syntax verifiable via `luac -p`.
- **FE Safety:** Client-side only (`Instance.new` in `Workspace`), non-colliding (`CanCollide = false`), massless to prevent map fling.
- **Naming & UI:** Toggle named `"Tux Ride 👑"`, Slider named `"Ride Speed"`, category `"Fun"`.
